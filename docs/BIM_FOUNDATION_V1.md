# Parametric BIM foundation V1 — bounded implementation batch

## Scope and repository audit

This batch implements Phase 2 data contracts and a minimal reusable assembly and
parameter dependency foundation. It does not register a new production executor,
change AI routing, change UI, or execute live model requests. Existing uncommitted
work was preserved.

Reused infrastructure:

- `app.domain.stage1.Contract`: camelCase aliases, forbidden extra fields, finite
  numbers and bounded IDs; `app.domain.ai3d.Primitive`: existing data-only geometry.
- AI3D V1 remains `ai-3d-design/1`. Its generic compiler emits boxes/cylinders;
  polygon extrusion is restricted to rectangles, sweep is planar and segmented,
  pipe is segmented cylinders, offset is straight/planar, arrays use simple templates.
- `Generic3DExecutor.execute_approved` already performs approved proposal checks,
  stale-source checks, unrelated component preservation, editable document conversion,
  ModelRevision persistence and `model_object_lineage` insertion.
- Building execution and patches use the same revision and lineage infrastructure.
- Assistant interactive flow has a 120-second timeout.

## Implemented contracts

`backend/app/domain/bim.py` defines `bim-project/1` with BIMProject, BIMAsset,
Assembly, Component, CrossSection, Material, Connection, Constraint, Parameter,
Dependency, GeometryDefinition and SourceProvenance. The checked-in JSON schema
is `docs/contracts/bim-project.schema.json`; a test detects schema drift.

Components carry stable explicit semantic IDs, asset/assembly memberships, types,
unit-bearing parameters, local placement, materials, relationships, dependencies,
source design/version/revision and validation status. Assemblies have explicit
memberships and placements. Limits cap the project at 250 components, 100 assemblies
and 250 dependency/constraint/connection records. Cross-section descriptors and
placements are data contracts only; there is no new profile or transform compiler.

`validate_foundation` checks unique identities, bidirectional membership and
reference consistency, material/section references, units, parameter ranges,
single dependency writers and cycles. It validates graph structure and parameter
constraints, not geometry or structural adequacy. It never upgrades validation status.

## Assembly and dependency behavior

`propagate_parameters` accepts explicit `(component ID, parameter ID)` updates
and an expected design version. It deterministically orders the dependency graph,
copies explicitly linked values, enforces constraints and returns a detached
candidate plus affected component IDs. Direct edits of driven parameters fail.
Unresolved dependency rules fail with `DEPENDENCY_REQUIRES_REVIEW`.

No source object is mutated on success or failure. Unchanged component identities,
geometry and metadata survive unchanged. Affected components become UNVALIDATED.
Geometry remains unchanged and must be regenerated by a future compiler: this API
is not a revision creation or geometry regeneration API. COPY does not infer girder
counts, engineering sizes or safe arrangements. Component-level cycle checking is
deliberately conservative.

## Persistence and workspace compatibility

No BIM tables, migrations or alternative persistence service were added. The next
integration should store the validated BIM snapshot in existing ModelRevision
document metadata, and bind each compiled component to existing object lineage.
Server-owned project IDs, approvals, placement and source revisions must be bound
and verified by the existing approved execution path, never trusted from AI JSON.
SourceProvenance is a storage contract, not an authorization mechanism.

No production workspace path imports the foundation yet. Existing Layers, Inspect,
selection, transforms, history and save/reload behavior are unchanged; interactive
BIM hierarchy handling and provenance displays are not implemented or UI-tested.

## Geometry and CAD decision

No wider geometry operation was added and no precise CAD kernel was adopted.
Current box/cylinder approximations cannot establish precise topology, boolean
openings, general profile sweeps or variable-section lofts. A kernel evaluation
must precede adoption and verify current licensing, distribution obligations,
Python/server deployment, native binaries, concurrency, tolerance handling,
meshing cost and Cesium editable representation. Open CASCADE is a candidate,
not an installed or evaluated integration in this batch.

## Demonstrations and boundaries

Automated fixtures reuse the same SUPPORT_FRAME assembly and COPY dependency
for BRIDGE and INDUSTRIAL_PLATFORM asset labels. This proves contract/dependency
reuse only. No detailed bridge hierarchy or industrial platform geometry was
generated. The richer superstructure, supports, abutments, foundations and secondary
elements demonstration is deferred until shared geometry compilation exists.

Engineering status is always UNVERIFIED. Unknown terrain, soil, loads and vertical
datum remain explicit by default. No engineering analysis, reinforcement approval,
foundation safety, seismic/code compliance, construction documentation or measured
quantities were implemented. Parameter validation is not geometric or engineering
approval. Reinforcement is a semantic type only, not a reinforcement design engine.

## Remaining work and stopping point

Stop before broader geometry or model requests. Remaining work includes trusted
provenance binding, deterministic parameter-to-geometry mappings, assembly expansion,
regeneration and approved atomic ModelRevision integration; staged checkpointed AI
authoring and durable jobs; detailed cross-asset demonstrations; hierarchy UI and
save/reload acceptance tests; and engineering modules with verified inputs.

Model-catalogue discovery and FAST evaluation preparation were deferred by the
execution instruction. No GLM ID was guessed, no routing changed, no paid evaluations
were run. Proposed paid request budget for this batch is **0 requests**. A later
evaluation batch must state an exact budget and obtain separate authorization.

Files added: the BIM contract module, pure foundation service, foundation test
module, BIM JSON schema and this implementation report.
