# StruvoCivil — Release Remediation Phase B

Completed locally on 23 October 2026 (Asia/Calcutta). **Launch remains BLOCKED.** No real-service qualification, deployment, SDK installation, credential change, paid inference or numerical execution occurred. Stop after Phase B for human review.

## Confirmed local fixes

1. **Legacy registration enumeration / B05.** Previously, production legacy registration returned a duplicate-address 409 versus a new-user/token response. `backend/app/api/routes/auth.py:register` now refuses all legacy production registrations with the same 403 before querying the address or writing data. This deliberately disables unsupported production onboarding; it does not pretend to implement a new recovery/account-verification flow. Development registration and existing-account password sign-in are preserved. `auth_configuration` exposes the non-sensitive `registration_allowed` capability; `frontend/lib/firebase-auth.ts` validates it and `app/login/LoginPageInner.tsx` hides signup and falls back to Sign in even for `?mode=register` when unavailable. Existing Firebase mode remains fail-closed.
2. **IP-only login abuse / A11/B17.** `services/rate_limit.py` now supplies an independent account-wide 10-attempt/60-second fixed-window quota in addition to the existing 20/60 IP quota. It keys normalized addresses with HMAC using the server secret, without putting raw email or an unsalted address hash in Redis keys. Redis pipeline expiration uses NX so rejected requests do not extend cooldown; this also makes existing Redis windows fixed, consistent with local memory behavior. Known/unknown accounts follow the same bucket path before lookup. Production still refuses memory fallback. No permanent account flag/lock was added. B17 improves from Missing to Partial, because real distributed behavior and lifecycle abuse policy remain unqualified. An attacker may still cause a temporary cooldown; this is documented, not sold as complete credential-stuffing prevention.
3. **Unknown/passwordless-account password-work discrepancy / B05.** Login now performs one real password verification using a non-user dummy hash when no usable account hash exists, then returns the same failed-login response. This narrows one timing discrepancy; different historical hash work factors, database/audit timing and genuine Firebase behavior are not proven constant-time. No stored hashes were rewritten.
4. **GeoJSON parser/input resource gaps / A14/A16/B06/B11.** Previously a decoded array could reach `.get()` and fail outside the intended validation path; arbitrary-size feature collections within the byte limit also reached reprojection/import loops. `services/upload_limits.py:validate_geojson_input` now preflights the entire collection's basic object/feature/geometry structure, finite numbers, maximum depth 32, total nodes 200,000 (including properties) and maximum 10,000 features before importing any geometry. Pending traversal growth is checked before extending the work stack. `services/survey/import_pipeline.py:ingest_geojson_file` rejects invalid Unicode and decoder recursion as validation errors. Valid coordinates are passed through unchanged. Existing 32 MiB file and archive bounds remain. Oversized formerly accepted inputs are intentionally rejected; this is not a replacement geometry engine or full topology/native-parser validator.
5. **Parser exception disclosure / A17.** `api/routes/survey.py:import_survey_data` no longer returns arbitrary native parser RuntimeError text in a 503 response. It returns a stable supported-format/configuration message. The synthetic regression injects a private-path/credential marker and checks it is not returned and no commit occurs. Other exception/error/log surfaces still need their own review; this is not blanket sanitization certification.
