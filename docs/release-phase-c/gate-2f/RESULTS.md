## Implemented

Reused the installed modular Firebase 13.1.0 SDK, existing login styling, API bearer transport, per-tab session boundary and backend UID-link authorization. No backend authentication or ownership code changed.

Three runtime frontend files changed:

- `frontend/lib/firebase-auth.ts`: independently gated Google/password providers; new `firebaseGoogleSignIn()` uses `GoogleAuthProvider`, user-initiated `signInWithPopup`, explicit popup resolver and `prompt: select_account`. Shared sign-in lifecycle rejects concurrent attempts, invalidates previous-account state before starting, suppresses premature SDK events, rejects late completion after logout/configuration changes, sanitizes popup/collision/signup errors and clears local authority on failure. Recovery additionally requires the password-provider gate.
- `frontend/app/login/LoginPageInner.tsx`: professional Continue with Google control alongside email/password, shared pending state, safe cancellation/blocking/collision messages and explicit access-denied feedback for unlinked identities. Either provider must complete `/api/auth/me` before navigation. Failure clears the same session without signing out a newer account. An additional session-revision assertion rejects stale completion. There is no registration, linking or Google OAuth-token extraction path.
- `frontend/components/auth/SessionBoundary.tsx`: retain the login component's pending/error state across SDK identity changes. Project and assistant views still remount on session revision; existing stores, account-specific caches and stale-response protections remain in force.

Three corresponding test files changed: `lib/firebase-session.test.tsx`, `app/login/LoginPageInner.test.tsx`, `components/auth/SessionBoundary.test.tsx`. Six final source hashes are recorded in `verified-source-hashes.json` and match the isolated tested copy.

`NEXT_PUBLIC_FIREBASE_GOOGLE_PROVIDER_ENABLED=true` is a **new opt-in configuration requirement**, not set in the normal project. Existing backend/browser/project/configuration gates also apply. No environment files, credentials or Web app registration were accessed or changed. With current defaults, Firebase stays unavailable; normal local login remains functional. The blocked backend ADC implementation and certificate default are byte-identical to Gate 2C.

No redirect flow, durable OAuth workaround, refresh-token copy, email-based internal merge, new account service or internal user provisioning was introduced. Backend project/file/result/history ownership gates remain authoritative on every request. Existing sign-out clears this tab; a subsequent Google attempt requests account selection. Neither operation claims to sign out the user's Google account or revoke every Firebase session.
