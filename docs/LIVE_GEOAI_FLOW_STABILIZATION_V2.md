# Live GeoAI Flow Stabilization V2

Implemented and verified offline. **No provider/model requests were made.** The complete live flow is not newly accepted by this milestone; a fresh user-flow test is still required. Qwen, token limits, temperature, timeout configuration, persisted AI3DDesign, primitives and Generic3DExecutor geometry remain unchanged.

1. **AREA root cause.** The saved first repaired design fit the argument schema and requested warehouse/parking/road decomposition, but exceeded both the selected AREA and project boundary. Its FOLLOW_ROUTE constraint required a route that did not exist. A later argument attempt also failed schema validation. Projection and validation correctly rejected that design; the missing integration was clear local bounds, applicable constraint guidance and a bounded design-validation repair.

2. **AREA representation.** Mandatory selectionContext now contains server-projected LOCAL_ENU geometry, the selected polygon, usable polygon intersected with the project boundary, bounding box, width/height in metres, centroid, coordinate ranges, selection type and applicable constraints. Orientation is supplied only from saved authoritative placement. Z remains UNKNOWN/local preview. A bounding box is not represented as the actual polygon. Selected model geometry is retained as compact required grounding; oversized required context fails explicitly rather than silently dropping it.

3. **Design repair.** Before proposal dispatch, the server normalizes compact input into the unchanged AI3DDesign, checks decomposition and runs saved-context/site/geometry validation. Only an explicit allowlist of conceptual errors is repairable: outside plot/boundary, wrong selection constraint, endpoint/route placement, zero-length path and bounded array-placement errors, among the declared placement checks. One direct PRIMARY completion returns design data only, using DesignIntent: systems, objects, relationships, constraints, explicit preview assumptions and unknowns. No proposal envelope, database references, history or repeated full system prompt. The server stamps identity/source/selection and reruns schema, decomposition, site and geometry checks. Failure immediately ends the attempt with DESIGN_REPAIR_FAILED; there is no repair loop or automatic shrinking/moving. Authorization, stale references, unsupported engineering capability and ownership errors are not repaired into passes. Existing outer/nested repairs remain bounded separately, within the same overall flow deadline.

4. **Bridge references.** Context separates selectionReference, siteProfileReference, modelRevisionReference and evidenceReference by kind. Evidence authority comes only from project-owned frozen profile associations and server tool results. A known selection/profile/model ID mistakenly placed in evidenceIds is excluded, with REFERENCE_TYPE_MISMATCH; only server-derived evidence reaches the persisted reply. Semantic aliases resolve through that registry. Arbitrary/unrecognized IDs still fail EVIDENCE_REFERENCE_INVALID; tool-derived evidence is checked for project ownership. This fixes the saved bridge's selection-ID/evidence-ID confusion without accepting that ID as evidence or relaxing ownership.

5. **Clarification.** Classification receives the available selection type and selected-component count. A deterministic guard suppresses only exclusive questions already answered by frozen context: two saved endpoints, a saved AREA, or exactly one selected component. Mixed questions and missing dimensions, soil, elevation, loads, distance or other genuinely absent information remain unsuppressed. No answer is inferred or invented.

6. **Selection constraints.** AREA advertises WITHIN_AREA and AVOID_AREA; ROUTE/CROSSING advertise FOLLOW_ROUTE, START_AT, END_AT and AVOID_AREA; ENDPOINTS advertises START_AT, END_AT and AVOID_AREA; POINT advertises conceptual placement and AVOID_AREA. AVOID_AREA still requires an actual resolvable polygon reference. Wrong selection/constraint combinations return CONSTRAINT_NOT_APPLICABLE. START_AT/END_AT also check the actual saved route/endpoint XY coordinates where relevant; preview Z is not turned into surveyed elevation. Unsupported engineering constraints continue to block generation. No new primitive or specialist was added.

7. **Proposal size.** On the unchanged valid saved bridge design, legacy arguments were 4,633 UTF-8 bytes; compact {design:…} arguments are 3,201 bytes: **30.91% smaller**. The outer arguments field changes from a serialized string of 5,195 bytes to a typed object of 3,215 bytes: **38.11% smaller**. The provider already uses JSON-object structured responses, so arguments do not inherently need a second serialization layer. ToolInvocation accepts bounded objects plus legacy strings; both must pass the same named tool argument validator. Compact generic input excludes source/selection/proposal IDs, provenance, capability state and derived parameters; these are stamped by the server. Existing BuildingSpec, BuildingPatch and legacy proposal contracts remain supported.

8. **Repair size.** Reconstructing the saved walkway's old nested-repair input with the checked-in pre-milestone context loaders gives 52,372 bytes. The new compact repair input, retaining the exact original malformed argument string and attached geometry, is 21,461 bytes: **59.02% smaller**. This is a reconstructed byte comparison, not a measured model token count. Representative expected generic repair output, using the valid saved bridge design, falls from 4,633 to 3,201 bytes (30.91%). There is no valid saved walkway output to measure; this output comparison is explicitly representative, not a rescored success. Specialist repairs retain their original necessary grounding.

9. **Stale preflight.** A new design/change operation compares the pinned model revision with the current revision in the relevant scenario before classification/provider execution. Mismatch returns CONTEXT_REFRESH_REQUIRED with zero calls. The UI tells the user to refresh selection and send a new message; it does not offer a retry of the stale frozen request. The retry endpoint also refuses that preflight failure. Historical retry contexts remain frozen for audit, never silently rebased; later proposal/build stale gates remain active. Unanchored site-free conceptual discussion remains available, because it has no frozen model to refresh and cannot persist site geometry.

10. **AREA replay.** Original saved design was not altered. Validation reports OUTSIDE_SELECTED_AREA, OUTSIDE_PROJECT_BOUNDARY and CONSTRAINT_NOT_APPLICABLE at the corresponding object/constraint paths. The result is DESIGN_REPAIR_ELIGIBLE with exact validator issues, applicable AREA constraints and the design-only repair contract captured. No repair request was sent.

11. **Bridge replay.** The saved valid proposal and final response now produce a valid review handoff offline. The selection-version ID is excluded from evidence, authoritative evidence is resolved, the unnecessary endpoint clarification is suppressed, and the PROPOSAL part references the real owned saved version. Replay is read-only; it did not publish a new chat message, alter approval, generate geometry or claim a new live pass. Runtime tests independently verify the COMPLETE reply and review part through a deterministic provider.

12. **Walkway replay.** Frozen source revision30 is stale relative to current revision31. A new operation returns CONTEXT_REFRESH_REQUIRED before a provider call. The original malformed arguments were retained unchanged for compact-input measurement, not manually fixed or converted into a valid design. No historical run was retried or rebased.

13. **Unknown safety.** Compact designs are stamped PREVIEW_ASSUMPTION. Ground elevation, soil/bearing, groundwater, survey, utilities, loads, capacity, foundations, code compliance and engineering approval remain unknown/unvalidated. Repairs must preserve original unknowns; removing them fails. Authoritative site facts remain in the frozen profile, while local visual Z remains a preview reference. Exact hashes, versioned assumption acknowledgement, user approval, build dependency gates and geometry-only validation remain required. No structural-engineering approval is implied.
