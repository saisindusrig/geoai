## Ranked findings and focused fixes

1. **High, confirmed and fixed: PDF text interpreted as resource-loading markup.** A synthetic project name reached ReportLab's image loader before the fix. The loader was intercepted; no external request occurred. See `pdf-reproduction-before.json`. Future PDF text is escaped, with only locally authored table-key bold markup retained. Regression malicious project/scenario/review fields no longer call the image loader. Historical PDFs were not regenerated. Files: `backend/app/services/exports/pdf_report.py`, `backend/tests/test_security_release.py`.
2. **High, partially remediated; release blocker remains: upload/parser resource abuse.** Survey content is now read with a 32 MiB + 1 bound after ownership/format checks; oversized content returns 413 and malformed ZIP returns 422. Archive preflight bounds 128 members, 64 MiB total expansion, 32 MiB/member and ratio 200; traversal, symlinks, encrypted/duplicate names are rejected before extraction. Full multipart ingress/spooling, expanded raster/point/mesh complexity, native parser sandboxing and malware handling remain unqualified. Files: `backend/app/services/upload_limits.py`, `backend/app/api/routes/survey.py`, `backend/app/services/survey/import_pipeline.py`.
3. **High, fixed configuration weakness: production rate limiter could downgrade to process memory.** Production now refuses requests with 503 when the shared backend is unavailable; local fallback remains. Production also refuses disabled rate limiting. No Redis service was provisioned. File: `backend/app/services/rate_limit.py`.
4. **High, unresolved qualification/data-loss blockers:** genuine identity lifecycle, PostgreSQL/PostGIS restore, private storage IAM/reconciliation, durable job leases/publication and distributed spending reconciliation. Mocked ownership tests establish useful code boundaries, not real Firebase or multi-instance readiness. Existing process locks and local ledgers are insufficient evidence for a distributed deployment.
5. **Medium, fixed: CSV formula-leading text.** Future CSV cells containing formula-leading strings are neutralized; numeric values, including negative engineering quantities, retain their values. This is defense in depth; no spreadsheet macro execution was attempted. File: `backend/app/services/exports/csv_export.py`.
6. **Medium, narrowed production configuration/header gaps.** Production CORS excludes default localhost, rejects wildcard preview policy and requires explicit HTTPS origins. Next responses add nosniff, DENY framing, strict-origin-when-cross-origin referrer policy and a partial CSP (`frame-ancestors 'none'; base-uri 'self'; object-src 'none'`). This does not meet the complete ASVS script-CSP requirement; no TLS/HSTS/deployed proxy claim is made. Files: `backend/app/core/production.py`, `backend/app/core/cors.py`, `frontend/next.config.ts`.
7. **High, conditional dependency/parser exposure remains.** Current installed leaf versions were compared with retained advisory ranges; inherited advisory comparisons use the actual affected leaf package, not the parent version. See `dependency-review.json`, `dependency-summary.json`, `DEPENDENCIES.md`. The retained 37 entries and old severity totals are historical audit entries, not a count of current exploitable vulnerabilities. Next 16.4.2/sharp 0.35.5 supersede the old Milestone 4 versions. No fresh registry/Python vulnerability scan, exploitation or package upgrade was run. Untrusted attribution/asset paths and build/test tooling have separate preconditions; request-to-vulnerable-function reachability is not established for every advisory.

## Authentication, assistant and engineering boundaries

Production JWT/secret checks remain; production SQLite and unavailable PostgreSQL refuse startup without fallback (tested). Official Firebase verification remains disabled without prerequisites, rejects unlinked identities and does not identify users solely by email. Genuine SDK/credential, revocation network behavior and lifecycle qualification remain blocked. Existing local identity must remain loopback development only. Current password hashing, MFA/recovery, key rotation and broader session controls require separate qualification.

Synthetic tests cover ownership, download/result gates, history isolation, malformed/forged/revoked identity outputs, protected CAD, exact revision/hash, stale results, preview approval, duplicate actions and undo/redo boundaries. A concurrent file-backed synthetic SQLite save produced one revision winner and one 409, preserving the base snapshot. This does not prove PostgreSQL or distributed save/storage crash atomicity.

AI output remains untrusted. Forged solver/save/approval tools and injected arguments fail whole-batch validation before execution. Existing tool allowlists, tool/turn bounds, quotas, ownership and frontend receipts remain. Nebius-only inference stays disabled, with no retries, offline fallback or spending activation. Prompt instructions in saved content cannot expand tool authority; semantic prompt-injection resistance and false prose claims are not proven by mocks. Frontend receipts describe visual outcomes, not independent engineering authorization. Live AI and distributed accounting remain unqualified. No numerical calculation was triggered.

Job recovery remains decision-only: interrupted/uncertain work cannot automatically rerun with old authorization. Atomic file publication is useful but does not establish atomic database/object-storage publication across worker crashes. Structural suitability, engineering methods and conceptual geometry remain independently restricted; no building generation, inferred connectivity or automatic analytical-member promotion was added. Legacy `/model` Cesium issue remains outside scope.
